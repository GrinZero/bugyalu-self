## 问题

原 RAG 引擎跨源召回率极低（接手时旧架构 `Context Recall@5` 仅 38%），且飞书、Slack、GitHub、Jira、Intercom 等多源知识孤岛、跨文档引用断裂；同时多 Agent 场景下存在检索越权风险、失效文档难清理以及代码变更影响面难评估的痛点。

## 方案

- **读写对称多源检索与多跳精排**：写路径统一摄取多源文档，引入新鲜度分层（`hot/warm/cold`）、生命周期管理与 LLM 富化（摘要、实体、潜在查询），私有 GCS 图文资产经无状态 HMAC 签名代理支持多模态检索；读路径设计 L0–L3 四级渐进降级预处理（实体识别、多语言改写、Mirror Text 假设回答段落），基于 Google Agent Search 多 Datastore 并行召回，叠加跨源 Reference 自适应多跳扩展（HopEngine）、跨 Query RRF 融合（`k=60`）、LLM Rerank 与相邻 Chunk 水合组装。
- **权限隔离与生命周期治理**：实现调用方 Token 级知识源权限绑定、RBAC 申请流，以及区分“排除未来同步”“手动删除检索投影”与“上游原文删除”的文档重建控制。
- **CodeGraph 代码图谱与私有 Skills 网关**：开发基于不可变 Worktree 与 SQLite A/B Generation 原子切换的 CodeGraph 代码图谱（支持符号调用链与 Open PR 增量影响面分析 MCP 工具），以及带 OAuth/RBAC 与全链路日志脱敏的私有 Agent Skills 分发网关（支持 `npx skills add/update` 一键安全安装）。

## 结果

通过 REST 与 MCP **统一服务内部全部核心 Agent（AskMoe 内部问答、客服 Agent、HR Agent、研发定位 Agent、QA Agent）**；在内部 LLM-as-judge 评测中，`Context Recall@5` 由旧架构 **38%**、重构初版 **60%** 持续跃升至 **71% → 82%**，`Answer Faithfulness` 由 **0.71 提升至 0.94**。
