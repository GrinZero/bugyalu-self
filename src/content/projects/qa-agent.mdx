## 问题

手工编写评审用例与 E2E 验证耗时长（单次常需一个下午），QA 个人经验难以跨项目复用；且早期 n8n 工作流在长时多轮调用中面临工具定义膨胀与大体积返回（如单次 Jira / PR 达 380k+ Token），极易撑爆上下文或静默超时。

## 方案

- **服务器拓扑与三层记忆体系**：设计 API / Split Orchestration Worker / Pooled Sandbox 执行隔离拓扑，推动系统向 TypeScript / Mastra Durable Agent 演进，落地公司首个云端 Agent。构建三层记忆体系——① 结构化 **Working Memory** 实时维护任务目标、覆盖边界与阻塞槽位；② **Observational Memory** 按 Token 水位自动触发轻量模型后台 **Observation 提炼与 Reflection 反思压缩**，支持跨会话分页 Recall 并严格隔离群聊共享与个人私有记忆；③ 基于 **PostgreSQL Advisory Lock + Revision 乐观锁 CAS** 实现跨会话 **User Memory**，安全沉淀长期测试偏好。
- **防过载 InputProcessor 流水线**：组装 `ToolSearchProcessor`（Top-K 动态按需挂载外部工具）、`ToolCallFilter`（跨轮次自动裁剪历史大体积原始工具输出，仅保留精简投影）、`TokenLimiter` 及到期前优雅收尾 Processor（预留窗口强制切 `toolChoice: none` 汇总结论）。
- **可信 E2E 持久闭环与评测治理**：建设支持 `suspend / resume` 的 E2E 持久工作流（冻结需求与 Base SHA → 隔离 Sandbox Author 编写与自检门禁 → Clean Verifier 全新工作区独立重放与录像采集 → QA 逐条审核及带反馈自动修复 → Draft PR 发布），并沉淀 Golden Dataset 与分项 Scorer 支撑回归评测。

## 结果

作为公司首个云端 Agent 持续服务内部 QA 团队，彻底解决长时任务上下文过载问题，并将 **E2E 环节耗时从一个下午缩短至约 1 小时**。
